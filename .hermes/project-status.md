- Frozen semantic boundary: the gateway consumes the existing `access-policy.v1` and `access-decision.v1` constructors/evaluator without changing their fields, enums, reason codes, or strict validator. Immediately before every reject/error decision or allow reservation construction, a shared gate enforces the exact frozen `observed_at <= time <= expires_at` freshness interval and raises typed `AccessGatewayPolicyError` outside the contract on drift. Only valid frozen robots outcomes emit a decision. SSRF, origin, HTTPS downgrade, redirect-hop, budget, policy-time drift, and transport-safety enforcement failures remain typed fail-closed gateway errors outside the frozen decision contract.
- Security behavior: configuration snapshots exact allowed origins into an owned `frozenset` and invokes the frozen access-policy identity validator before any transport can receive the transparent user agent, so caller mutation cannot expand authority and digest-correct sensitive identity text fails with zero requests. The default transport is the established proxy-disabled `SafePinnedTransport`, which resolves all addresses, rejects non-public addresses, pins the selected peer, validates peer/SNI/Host, and exposes no automatic redirects. After socket acquisition, a single pre-response `finally` closes the raw socket on every classified failure, ordinary unclassified exception, or propagating `BaseException`; ordinary unclassified failures become typed safety `TransportFailure` while cancellation semantics are preserved. After a response arrives, cleanup ownership remains with the transport through header processing and complete `RawHttpResponse` construction; a handoff flag is set only after successful construction, so header/build exceptions and cancellation close response, connection, and socket while successful return is not prematurely closed. The gateway then owns the handed-off final response across complete response-metadata copying and consumer execution, so ordinary or cancellation failures during header copying close raw before any consumer/write. Every initial or redirect content hop is canonicalized, checked against the exact configured origin set, protected from HTTPS downgrade, and sent through a fresh safe transport request; robots is reevaluated for that origin before the content request. Disallowed/error decisions occur before opening target content and before invoking the caller's response consumer. Every returned robots 200 response is explicitly closed by a gateway-owned `finally`, including successful parsing and early body/parse/evidence failure. TLS body safety failures remain typed gateway transport errors rather than parser outcomes. The pure core performs no file, temporary-file, or storage writes.
- Redirect behavior: redirects are handled manually. `max_redirect_hops` is an exact bound: zero permits no followed redirect, one permits exactly one, and the next redirect fails closed. Origin expansion and HTTPS downgrade are rejected before a request to the redirected target.
- Robots behavior: the cache key is exactly SHA-256 over canonical origin plus the transparent identity digest plus literal `access-policy.v1`, using the frozen contract helper. Entries obey contract-bound TTL/freshness, exact-origin or global invalidation, and generation-safe concurrent single-flight. Offline tests cover valid 200 allow/disallow, 404, 401, 403, timeout, DNS error, network error, parse failure, cache hit/expiry/invalidation/single-flight, and invalidation during an in-flight fetch. Any HTTP status outside the frozen 200/401/403/404 matrix, including 418 and 503, closes the response and raises a typed gateway error outside `access-decision.v1`.
- Reservation settlement: per-origin state atomically checks hard budget and reserves the next pacing slot before a content request. Before constructing a reservation, the complete half-open budget window must contain `not_before`; an invalid paced slot raises typed `AccessGatewayBudgetError`, consumes no unit, opens no target transport, and releases the lock. The origin start lock is held through the transport start so concurrent same-origin requests cannot race; different origins have independent locks and state. Once reservation succeeds, its budget unit is irreversibly consumed on success, cancellation, timeout, transport error, consumer error, or an oversleep/clock jump beyond policy or budget-window authority to prevent retry amplification. After pacing, the actual prospective start is rechecked against both boundaries before transport. Locks and response/connection handles are released in `finally`; denied or pre-reservation failures consume no reservation.
